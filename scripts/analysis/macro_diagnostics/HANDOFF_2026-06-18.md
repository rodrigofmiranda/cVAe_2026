### Diagnóstico que motivou o E1 (de REDESIGN_PLAN.md + memória)
Dois problemas distintos, **ambos de dados/loss, não de arquitetura**:
- **(A) fronteira near-field alto-SNR**: 0.75 m é TREINADA, tem o MAIOR SNR (17.9 dB)
  e mesmo assim falha 0/9; gates são RELATIVOS → é precisão relativa em alto SNR.
  Fix: loss de erro relativo / oversample ∝1/σ / especialista d≤0.9 m.
- **(B) interpolação de distância**: grid {0.75,1.0,1.35,1.5} tem gap 0.35 em 1.0–1.35
  onde caem 1.16/1.25. Fix: densificar p/ {0.75,0.9,1.0,1.16,1.35,1.5}.
- Corroboração: S1–S2 Gaussiano já fez 10/12 → **decoder Gaussiano basta**; parar de
  mirar capacidade de cauda do MDN (negativos S28/S29/S33 já provados).

## 4. Gotchas operacionais (LER antes de lançar qualquer coisa)

- **Host = 64 GB RAM é o teto, NÃO a GPU (32 GB).** Rodar 2 treinos TF em paralelo
  **estoura a RAM** (a réplica concorrente morreu por OOM-killer no epoch 2; sem
  traceback = SIGKILL; swap estava 5.5/8 GB). → **Treinos cVAE rodam SEQUENCIAIS aqui.**
- **Proxy de fila correto = uso REAL da GPU** (`nvidia-smi --query-gpu=memory.used`),
  **não** presença de container. O `trigger_v3fc_e1gauss.sh` original travou porque
  esperava o container `cvae_eduardo` sumir, mas ele ficou "Up" como shell ocioso
  para sempre com a GPU livre.
- **NÃO tocar no `cvae_eduardo`** (run de outro usuário; hoje é shell ocioso).
  `/home/eduardo` é permission-denied p/ rodrigo (ler só via container root :ro).
- **Padrão de lançamento** (todos os scripts seguem): `docker run -d --rm` +
  `--runtime=nvidia`, monta `-v $REPO:$WORKDIR -v /home/rodrigo/1-Data:/data:ro`,
  `-e TF_FORCE_GPU_ALLOW_GROWTH=true` (se for coexistir), detached via `setsid nohup`
  para sobreviver a cortes do harness. Ver `launch_v3fc_e1gauss_now.sh` como modelo.
- **ntfy**: todo run longo avisa em `https://ntfy.sh/projeto_vlc_ia`. Rodrigo larga o
  terminal — sempre deixar watcher/notificação.
- **Seed**: usar 33 (ou outras), **evitar 42** (uso excessivo).
- **GRU**: no V3 o kernel cuDNN fundido falha → fallback automático
  `seq_gru_backend='compat'` (funciona, mais lento). Esperado, não é erro.
